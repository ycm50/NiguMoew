# 交易大亨 TradeTower

> **纯单机模拟游戏。不涉及任何真实资金、充值、提现或支付。**
> 游戏里的"钱"是模拟数字，作弊器也是模拟功能。

C++ 引擎 + Java Swing 前端的**股票 / 外汇交易模拟游戏**。

## 下载即玩

到 [Releases](../../releases/latest) 下载 **`trade-tower-x.y.z-win64.zip`**：

1. 解压到任意目录
2. 双击 **`play.bat`**

## 从源码构建

前置条件：**Windows** + **JDK 17**（设好 `JAVA_HOME`，或装在 `A:\jdk-17.0.12`）+ PATH 里的 **g++**（MSYS2 ucrt64 / MinGW）。

```cmd
scripts\build.cmd        :: 编译引擎 + 前端 + 工具
scripts\run.cmd          :: 启动游戏（也可直接双击 play.bat）
scripts\selftest.cmd     :: 全量自测，退出码 0 = 全绿
```

打包发行版：

```powershell
pwsh -File scripts\package.ps1 -Version 1.0.0
# 加 -SkipJre 可产出体积更小的包（用户需自备 Java 17）
```

## 架构

```
┌─────────────────────┐   stdin/stdout 上的单行 JSON   ┌──────────────────────┐
│  Java Swing 前端     │ ◄────────────────────────────► │  C++ 引擎            │
│  frontend/src/tsim   │   子进程，协议 v1.0.1（冻结）    │  engine/src          │
└─────────────────────┘                                └──────────────────────┘
```

- 引擎日志走 **stderr**，stdout **只允许**出现协议 JSON 行。
- 自动时钟推进时引擎**主动推送** `{"id":0,"push":true,"type":"tick"|"bankrupt",...}`。
- 契约全文见 [docs/PROTOCOL.md](docs/PROTOCOL.md)。

### 目录结构

```
engine/src/        C++ 引擎（json/util/market/news/account/order/engine/clock + main.cpp）
frontend/src/tsim/ Java Swing 前端（json / ui / tests）
tools/             jsoncheck（JSON 行校验器）、driver（端到端驱动）
engine/tests/      单元冒烟 + QA 契约/业务验证器（独立实现，不复用被测代码）
scripts/           build.cmd / run.cmd / selftest.cmd / package.ps1 / srcfingerprint.ps1
.github/workflows/ release.yml —— 构建、打包、发布即玩版
docs/PROTOCOL.md   引擎↔前端通信协议
```

## 发布流程

`.github/workflows/release.yml` 在 push 到 `main` / `master`、打 `v*` tag，或手动触发时运行：

1. **计算版本号** —— 从 `1.0.0` 开始；**每段最高 9**，从个位逐位进位：
   `1.0.0 → 1.0.9 → 1.1.0 → 1.9.9 → 2.0.0`（永不出现 >9 的段）
2. **构建** —— 装 MSYS2(ucrt64) + JDK 17，跑 `build.cmd`
3. **自测** —— 跑 `selftest.cmd`，**不全绿直接失败，不允许发布**
4. **打包** —— 调 `scripts/package.ps1` 产出即玩 zip + `SHA256SUMS.txt`
5. **冒烟** —— 解压产物，验证引擎自检通过、随包 JRE 能启动 GUI
6. **发布** —— 上传到 GitHub Release（文件 + 校验和 + 自动生成的发布说明）

手动触发可指定版本号，或勾选"标记为预发布"。

## 工程纪律

开发过程中固化在 [CONTRIBUTING.md](CONTRIBUTING.md) 的几条经验（都踩过坑）：

1. **构建必须幂等** —— 源码未变则跳过链接，否则"跑一次自测"就会改写定版二进制、污染别人的回归判据。
2. **冻结判据是二元的** —— 源码指纹（`scripts\srcfingerprint.ps1`）判"代码是否变化"；
   exe 哈希只判"**同一轮内**二进制是否被替换"，**跨轮比较无意义**（MinGW 的 PE 头含链接时间戳，
   同一份源码重链接必得不同哈希）。
3. **断言错了也要被验伪** —— 期望值取运行期实际值，禁止硬编码魔数。
4. **口径要实测校准** —— 协议措辞与实测不符时，以独立复核的实测为准。
5. **入口类必须端到端验证** —— 只测组件会漏掉"引擎路径解析错了但界面照常显示"这类缺陷。
